## 营业准备

管理员首次登录后，在“菜品与桌台”录入分类、菜品价格及桌号，并在“员工与记录”新增收银、后厨和店长账号。分类、菜品和桌台可暂停使用；桌台有未结订单时不能停用。每人可在右上角“改密码”自助更换密码，修改后须重新登录。门店开始收款前，由一名员工在“交班”登记备用金并开启共用钱箱；同店其他收银员无需重复开班。正式门店应更换强密码、仅允许受信任的内部网络访问，并每日备份。

## 点单至收银

1. 收银台新建堂食或外带订单。堂食需选择空桌，外带不占桌；堂食订单可换至其他空桌。
2. 先选择订单，再点菜品卡片直接加一份；可用“加菜（数量/备注）”一次添加多份并填写口味。未送厨的菜品可点“编辑”修改数量和备注。点击“送后厨”后生成票据；再次加菜只发送本次新增部分。
3. 未送厨菜品可由收银员更正数量；已送厨退菜由店长录入原因并通知后厨。需要分别结账时，可在拆单窗口选择多道菜及数量。整单折扣由店长录入，拆单前应先清除原单折扣。
4. 收银前先确认后厨已收到全部未退菜品。现金收款录入实收金额，系统计算找零；外部终端收款须**先在独立终端确认成功**，再选择人工登记并录入交易号。本系统不会自行完成或验证外部支付。
5. 已结账订单可用浏览器打开并打印小票。店长可对现金订单登记全额退款；外部终端退款须先在独立终端完成并核对，再在本系统填写退款交易号登记。系统不会发起或验证终端退款。

多个收银页面每 5 秒读取一次最新订单。别人改过账单后，页面会提示重新核对；若修改发生在确认窗口打开期间，提交会被拒绝，刷新后按最新金额重新操作。网络中断时应先恢复连接并刷新，避免依据旧画面收款。

营业中钱箱存入或取出现金，先在“交班”登记金额和原因。收款、退款和现金存取都记录操作人。开班人或店长交班时录入实际点数的现金，系统按共用钱箱的备用金、所有员工的现金收退款和现金收支计算应有金额、差额，并保留开班人与交班人；差额需按门店制度核查。若仍有未结订单，交班页显示笔数和应收，交班人须确认；这些订单留在系统中由下一班处理。清点期间若钱箱余额或未结订单变化，交班会被拒绝，须重新核对。作废、折扣、退菜、退款与员工修改会留操作记录。

## 备份与恢复

运行 `POS_DB_PATH=./data/pos.sqlite npm run backup -- ./backup-YYYYMMDD.sqlite`。程序使用 SQLite 一致性快照生成备份，并做完整性检查。备份包含订单、员工及密码散列，应按门店数据管理要求保密保存，建议至少保留异地副本并定期演练恢复。

恢复步骤：停止服务；复制并保留当前数据库以及同名的 `-wal`、`-shm` 文件；将经验证的备份复制到配置的 `POS_DB_PATH`；确保目标位置没有旧的同名 WAL/SHM 文件；启动服务，在测试环境核对登录、历史订单、钱箱、报表，并试建及结清新订单。不要在服务仍运行时直接覆盖数据库。升级前先备份并测试恢复；旧版若有多个未交班个人班次，先用旧版逐一实点交班，新版不会自动合并这些现金账。若新版本不兼容旧数据，应使用匹配版本的程序与备份回退。

## 故障处理

- 无法结账：确认收银员已开班、订单有菜品、所有未退菜品已发送后厨。
- 后厨没看到票据：检查是否点击“发送后厨”、是否已完成票据，以及浏览器网络连接。页面刷新后重新读取未完成票据。
- 外部终端付款状态不确定：以终端交易明细和收单方对账结果为准；避免重复收款。POS 的人工记账记录不能作为到账证明。
- 数据库无法打开：检查卷挂载、文件权限和磁盘空间；使用备份恢复前先保留故障现场文件。
